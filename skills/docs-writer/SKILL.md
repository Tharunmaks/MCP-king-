# Docs Writer

README order: what it is (one sentence) → screenshot/demo → quick start (copy-paste commands that work) → usage examples → configuration → troubleshooting → license.

- Lead with the reader's goal, not the history of the project.
- Every command must be copy-pasteable and tested. Show expected output when helpful.
- Use short sections, tables for options, and code blocks with language tags.
- Platform differences (Windows/macOS/Linux/Android) get their own small blocks.
- No marketing filler ("blazing fast", "revolutionary"). Use concrete numbers instead.
- Comments in code explain *why*, not *what*.
